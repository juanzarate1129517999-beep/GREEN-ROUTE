Conceptos del curso

Cada concepto de POO, en el código

1 · Clases y objetos · encapsulamiento

Datos privados, acceso controlado

Todos los atributos son private final y se validan en el constructor: no es posible crear un vehículo con capacidad negativa ni una coordenada fuera de rango. El exterior solo lee mediante getters; el riesgo de un tramo solo se modifica por un setter que acota el valor entre 0 y 1.

Vehiculo.javaCoordenada.javaTramoVial.java
public abstract class Vehiculo implements Emisor {
    private final String id;
    private final double capacidadKg;

    protected Vehiculo(String id, ..., double capacidadKg, ...) {
        if (capacidadKg <= 0) {
            throw new IllegalArgumentException("Parámetros físicos inválidos");
        }
        this.capacidadKg = capacidadKg;
    }
    public double getCapacidadKg() { return capacidadKg; }
}

2 · Herencia

Jerarquía de vehículos de tres niveles

Vehiculo → VehiculoTerrestre → CamionDiesel → Tractocamion. El tractocamión reutiliza todo el modelo de consumo del camión diésel y solo cambia sus parámetros a través de super(...). Lo mismo ocurre con los tramos: Tramo → TramoVial / TramoFluvial.

Tractocamion.javaCamionDiesel.javaVehiculoTerrestre.java
/** Hereda el modelo de consumo del camión diésel: solo cambia parámetros. */
public class Tractocamion extends CamionDiesel {
    public Tractocamion(String id, String nombre) {
        super(id, nombre, 34_000, 15_000, 70, 33.0, 0.30, 1_100);
    }
    @Override
    public String getTecnologia() {
        return "Tractocamión articulado diésel (contenedores)";
    }
}

3 · Polimorfismo

Una misma llamada, siete respuestas

El optimizador invoca vehiculo.calcularEmisionKgCO2(tramo, ctx) sin saber qué vehículo es. Java despacha en tiempo de ejecución al consumoPorKm de la clase concreta: litros de diésel, m³ de gas o kWh. La barcaza redefine puedeCircularPor para aceptar solo el río; los terrestres lo redefinen para evitar el río y los carriles del Transmetro.

CriterioEmisiones.javaBarcaza.javaCamionElectrico.java
// CriterioEmisiones.java — no conoce la clase concreta
public double costo(Tramo t, Vehiculo v, ContextoViaje c) {
    return v.calcularEmisionKgCO2(t, c);   // enlace dinámico
}

// CamionElectrico.java
@Override
protected double consumoPorKm(double v, double carga) {
    return consumoReferenciaKWhKm(carga) * curvaVelocidad(v, 0.85, 5.0, 0.00009);
}

4 · Abstracción

Clases abstractas con métodos plantilla

Vehiculo, VehiculoTerrestre, Tramo y BusquedaCaminoMinimo son abstractas: no se pueden instanciar y declaran métodos sin cuerpo que las subclases están obligadas a implementar. En BusquedaCaminoMinimo todo el algoritmo es común; Dijkstra y A* solo difieren en heuristica().

BusquedaCaminoMinimo.javaDijkstra.javaAEstrella.java
public abstract class BusquedaCaminoMinimo implements AlgoritmoRuta {
    protected abstract double heuristica(Nodo n, Nodo destino, double cota);
    public final Ruta buscar(...) { /* cola de prioridad común */ }
}
public class Dijkstra extends BusquedaCaminoMinimo {
    protected double heuristica(...) { return 0.0; }
}
public class AEstrella extends BusquedaCaminoMinimo {
    protected double heuristica(Nodo n, Nodo d, double cota) {
        return n.getCoordenada().distanciaMetros(d.getCoordenada()) * cota;
    }
}

5 · Interfaces

Contratos con métodos por defecto

Emisor, Recargable, FuncionCosto y AlgoritmoRuta definen capacidades. Un camión eléctrico es a la vez Vehiculo (herencia) y Recargable (interfaz). Recargable trae métodos default que calculan la autonomía a partir de los métodos abstractos que cada clase implementa.

Recargable.javaEmisor.javaFuncionCosto.java
public interface Recargable {
    double getCapacidadBateriaKWh();
    double consumoReferenciaKWhKm(double cargaKg);

    default double autonomiaKm(double cargaKg) {
        return getCapacidadBateriaKWh() * 0.90 / consumoReferenciaKWhKm(cargaKg);
    }
}
public class CamionElectrico extends VehiculoTerrestre implements Recargable { ... }

6 · Composición y agregación

Objetos formados por otros objetos

Composición (el todo crea y es dueño de sus partes): RedTransporte crea sus Nodo, cada nodo posee su lista de Tramo salientes y Flota controla su lista de vehículos sin exponerla modificable. Agregación (las partes existen por sí solas): un Envio referencia una Mercancia y dos Coordenada; el PlanificadorRutas recibe la red, la flota y el perfil ya construidos.

Flota.javaRedTransporte.javaEnvio.java
public class Flota {
    private final List<Vehiculo> vehiculos = new ArrayList<>();

    public void agregar(Vehiculo v) {
        if (vehiculos.contains(v)) throw new IllegalArgumentException("Duplicado");
        vehiculos.add(v);
    }
    public List<Vehiculo> getVehiculos() {
        return Collections.unmodifiableList(vehiculos);   // nadie la altera desde fuera
    }
}

7 · Excepciones propias

Errores del negocio con jerarquía

GreenRouteException es la excepción verificada base, con un código de error. De ella heredan CapacidadExcedidaException, AutonomiaInsuficienteException, VehiculoIncompatibleException, RutaNoEncontradaException y DatosInvalidosException. El servidor las captura en un solo punto y las convierte en mensajes claros para el usuario (por ejemplo, «la barcaza solo opera entre puntos ribereños»).

        throw new CapacidadExcedidaException(nombre, cargaKg, capacidadKg);
    }
}

Diseño

Patrones de diseño aplicados

Strategy

Criterios intercambiables

Cinco implementaciones de FuncionCosto (emisiones, tiempo, distancia, riesgo, eco-balanceado). El algoritmo de búsqueda no cambia al cambiar de criterio.

Template Method

Algoritmo con pasos variables

BusquedaCaminoMinimo.buscar() fija el esqueleto y delega la heurística; Vehiculo.calcularEmisionKgCO2() fija la fórmula y delega el consumo.

Facade

Un punto de entrada

PlanificadorRutas oculta la red, la flota, el perfil horario y el algoritmo detrás de métodos simples: planificar, alternativas y compararFlota.

Factory

Creación centralizada

Criterio fabrica la estrategia de cada criterio (crearFuncion()) y Flota.flotaDeReferencia() construye la flota de demostración.

Integración

API REST del motor

Parámetros comunes: olat, olon, dlat, dlon (origen y destino), vehiculo, criterio, hora (0-23) y carga (kg). Los errores del dominio responden con HTTP 422 y un JSON con error y mensaje.

Método y rutaDescripción
GET /api/estadoTamaño de la red, algoritmo activo y perfil horario de tráfico.
GET /api/vehiculosFlota con clase, superclase, energía, capacidad y batería.
GET /api/puntosPuntos logísticos geocodificados (puerto, zona franca, aeropuerto…).
GET /api/rutaRuta óptima para un vehículo y un criterio, con geometría e indicaciones.
GET /api/alternativasLa mejor ruta del vehículo bajo cada uno de los cinco criterios.
GET /api/compararEvalúa toda la flota y recomienda el vehículo de menor emisión.
GET /api/algoritmosCompara Dijkstra y A* (nodos explorados y tiempo de cálculo).
